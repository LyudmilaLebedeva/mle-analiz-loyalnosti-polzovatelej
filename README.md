# Анализ лояльности пользователей

Проект для загрузки, обработки и анализа данных о покупках на Яндекс.Афиша с целью построения профилей пользователей и оценки их лояльности.

[![GitHub](https://img.shields.io/badge/github-LyudmilaLebedeva%2Fmle--analiz--loyalnosti--polzovatelej-6f42c1?style=flat&logo=github)](https://github.com/LyudmilaLebedeva/mle-analiz-loyalnosti-polzovatelej)

## Возможности

- **Загрузка данных** из PostgreSQL и по HTTP (CSV) с кэшированием в CSV-файлы
- **Конвертация валют** — автоматическая конвертация тенге (KZT) в рубли (RUB) по курсу ЦК
- **Оптимизация типов** — downcast числовых колонок, приведение к `category` и `datetime`
- **Очистка данных** — удаление выбросов по квантилям/границам и дубликатов
- **Построение профилей** — агрегация по пользователям (первый/последний заказ, кол-во заказов, средняя выручка, интервалы)
- **Сегментация** — создание категориальных колонок на основе числовых признаков
- **Анализ** — статистика по сегментам, матрица корреляций Phik для смешанных типов данных
- **Тестирование гипотез** — проверка двух бизнес-гипотез (тип первого события, активность региона)
- **Резюме** — автоматическое формирование итогового отчёта с выводами и рекомендациями

## Установка

1. **Создайте виртуальное окружение:**

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

2. **Установите зависимости:**

   ```bash
   pip install -r requirements.txt
   ```

3. **Настройте переменные окружения:**

   ```bash
   cp .env.example .env
   ```

   Заполните `.env` данными подключения к PostgreSQL:

   ```env
   DB_USER=your_username
   DB_PWD=your_password
   DB_HOST=your_host
   DB_PORT=5432
   DB_NAME=your_database
   ```

## Что делает скрипт

1. Загружает данные о покупках из PostgreSQL (`afisha.purchases`) с фильтрацией по типу устройства (`mobile`/`desktop`) и типу события (не «фильм»).
2. Загружает курс тенге по датам из внешнего CSV.
3. Конвертирует выручку в рубли, оптимизирует типы данных, удаляет выбросы и дубликаты.
4. Строит профили пользователей (агрегация по `user_id`), создаёт сегмент по количеству заказов.
5. Выводит статистику сегментов по типу устройства, региону, типу события.
6. Проверяет гипотезы:
   - **Гипотеза 1**: тип первого события (спорт vs концерты) влияет на повторную покупку — **НЕ подтверждена** (концерты дают +6.8% повторных покупок).
   - **Гипотеза 2**: активность региона коррелирует с долей повторных покупок — **НЕ подтверждена** (rho = 0.079, p = 0.83).
7. Строит и выводит Phik-матрицу корреляций между признаками профилей.
8. Формирует итоговое резюме с ключевыми числами, результатами гипотез и рекомендациями.

## Выводы по анализу данных

1. Качество и объём данных

Исходный датасет содержал 290 611 транзакций, которые после агрегации сформировали профили 21 700 уникальных пользователей.
При очистке удалено 8 732 записи (3.0%) как выбросы по выручке — это свидетельствует о наличии аномальных крупных или мелких транзакций.
Дубликаты практически отсутствуют (39 шт., 0.01%), что говорит о хорошем качестве исходных данных.
Оптимизация типов данных дала 6× экономию памяти (196 → 33.8 МБ) — проект хорошо масштабируется.

3. Предпочтения по типу устройства

   82.9% пользователей, чей первый заказ был с мобильного устройства, 17.1% — с десктопа.
   Доля двухсуммарных пользователей (is_two_sum) сопоставима: 61.2% на мобильных и 64.1% на десктопе — разницы в поведении между устройствами практически нет.
   Рекомендация: приоритет в разработке — мобильный опыт (UX, перформанс, push-уведомления).

6. Проверка гипотез

    **Гипотеза 1**: пользователи, чей первый заказ на спорт, совершают повторную покупку чаще, чем пользователи с первым заказом на концерты.
    - Концерты: 62.1% повторных покупок, Спорт: 55.3%
    - Разница: −6.8%, z = −3.738
    - **НЕ подтверждена**: первый заказ на концерты ассоциирован с более высокой долей повторных покупок.

    **Гипотеза 2**: в регионах с большим числом пользователей выше доля повторных покупок.
    - Спирмен: rho = 0.079, p-value = 0.8287
    - **НЕ подтверждена**: связи между числом пользователей в регионе и долей повторных покупок нет.

7. Корреляционный анализ (Phik-матрица)

   Сильнейшие связи:

region_name ──── event_type_main r = 0.52 ★
region_name ──── avg_revenue_rub r = 0.36 ●
event_type_main ── avg_revenue_rub r = 0.32 ●
total_orders_segment ── avg_revenue_rub r = 0.29 ○
Ключевые выводы из корреляций:

Регион ↔ Тип события (0.52) — самая сильная связь в датасете. Пользователи разных регионов посещают принципиально разные события. Это подтверждает необходимость регионально-персонализированных предложений.
Регион ↔ Выручка (0.36) — регион существенно влияет на средний чек. Есть «высокодоходные» и «низкодоходные» регионы.
Тип события ↔ Выручка (0.32) — категория события влияет на сумму покупки. Концерты и театр, вероятно, генерируют более высокий средний чек, чем ёлки или выставки.
Кол-во заказов ↔ Выручка (0.29) — умеренная связь. Медианная выручка повторных покупателей (506 ₽) выше, чем у разовых (389 ₽), но средняя выручка почти одинакова (551 vs 553 ₽) из-за выбросов с высокой суммой. Это говорит о том, что лояльные пользователи в среднем тратят больше за покупку, но разброс очень большой.
